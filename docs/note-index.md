# Markdown 持久化索引

Scholar Sketch 使用 Zotero 的 `DBConnection`，在 Zotero 数据目录中创建
`scholar-canvas/scholar-canvas.sqlite`。这是插件自己的可重建缓存，不修改 Zotero 核心表，
也不通过 Zotero 附件同步上传。Markdown 附件仍是原始数据。

## 保存的数据

- `notes`：以 `(libraryID, noteKey)` 为主键，保存文件名、标题、群组 ID、
  文件路径、修改时间、大小和 Markdown 正文。
- `links`：保存来源笔记、链接地址、显示文字、语法类型和原文起止位置。
  同一笔记内重复出现的链接分别保留。
- `notes_search`：宿主支持 FTS5 的 trigram 分词器时建立的全文候选索引，覆盖标题、
  文件名及正文。使用笔记行号定位更新，避免每次保存遍历整个全文索引。
- `notes_search_state`：记录全文索引是否需要重建。曾在不支持 trigram 的宿主中修改缓存后，
  下次在支持的宿主打开时自动从 `notes` 重建。
- `PRAGMA user_version`：当前模式版本为 2。版本 1 自动保留笔记、链接记录并建立全文候选索引。
  今后修改表结构或解析规则时需更新版本
  并实现迁移或重建；较新版本的数据库会被保留，旧插件回退读取 Markdown。

目标笔记仍基于当前文库元数据解析，避免重命名或新增同名文件后复用过期的匹配结果。

## 全文搜索

全文索引只用于缩小候选范围，结果仍由 JavaScript 的 Unicode 大小写不敏感字面子串匹配
验证，保留多词 AND、标题/文件名命中、正文定位及不可读文件过滤的原有语义。
查询片段至少包含 3 个字符时才可能使用 trigram；短词以及不能安全映射大小写的片段
回退到内存快照扫描。例如“中文”回退扫描，“中文全文搜索”可以使用候选索引。
ASCII 大小写、长 s（ſ）和 Kelvin 符号（K）的等价关系在写入及查询时一致处理，
其他 Unicode 片段只在不含大小写变化的情况下用于缩小候选范围。

首次搜索仍校验文库附件状态；后续查询复用有效的内存快照，不重复读取全部文件。
候选索引必须与快照处于同一保存代次；保存、失效或扫描抢占发生时等待更新，必要时
重新同步候选索引。无法确定索引完整性或宿主不支持 FTS5/trigram 时扫描当前快照，
不把索引不可用解释为空结果。

扫描与结果验证按批次让出事件循环。输入变化、关闭窗口或文库内容变化立即使旧查询失效，
旧结果不能覆盖新查询。界面逐批显示前 100 个匹配，计数包含全部匹配；不会为全部结果
创建 DOM 节点。索引初次构建/升级仍有一次性开销，单个特别大的文件仍需完整匹配。

## 更新与一致性

首次访问一个文库时枚举现有 Markdown 附件，并加载 SQLite 缓存。路径、修改时间和
大小一致的文件复用正文及解析结果；变化的文件重新读取，读取前后文件状态一致才记下
可复用的状态。手工保留修改时间且保持大小的编辑需要使用强制刷新。

保存 Markdown 后，即使没有打开反向链接面板，也会排队更新数据库。保存路径不依赖
索引成功；数据库异常只记录日志并在本次运行中停用缓存，原文件照常保存。
不支持 FTS5/trigram 时仅关闭全文候选加速，普通笔记与链接缓存仍可使用。

所有数据库操作排队执行。文库扫描的写入使用事务，并在事务中检查扫描是否已被新保存
或缓存失效事件取代；过期扫描会回滚。正文、链接与全文候选更新在同一事务内提交。
完整扫描会清理该文库内已删除、已移入回收站或
无法读取的笔记缓存。未发生变化的记录不重复写入。

Zotero 条目/文件通知及切回应用会使内存缓存失效，下次扫描校验文件状态。
打开的反向链接面板会触发扫描。插件关闭时等待已排队操作完成并关闭连接。
同步完成后，仅对已加载且存在读取失败的文库重新校验，以处理下载未发送文件通知的情况。

反向链接面板中的未索引数量统计当前文库中其他读取失败的 Markdown 笔记，
不表示当前笔记损坏；附件自身或其父条目已在回收站时不参与统计。
展开提示可查看具体标题及未下载、本地不可用、读取或解析失败的原因，点击标题仅定位条目，
不会自动下载附件。面板最多显示 10 条诊断，完整数量仍会保留。

## 重建

反向链接面板的“刷新”按钮强制从当前文库的 Markdown 文件重新读取并解析，
不受缓存文件状态匹配影响。程序入口为 `rebuildNoteLibrary(libraryID)`。

数据库无法打开或损坏时，可退出 Zotero 后移走插件的
`scholar-canvas/scholar-canvas.sqlite` 及同名前缀的 SQLite 日志文件，再启动重建。
不要移除 Zotero 自身的 `zotero.sqlite`。数据库缓存无需作为笔记备份；备份应包含
原始 Markdown 及其资源附件。

## 验证

`test/document-links-index.test.ts` 使用 Node 的真实 SQLite 引擎运行生产 SQL，覆盖
重新打开数据库、重复链接、文库隔离、删除清理、事务回滚、保存并发、文件状态校验、
强制重建和索引错误回退。`test/document-links-search.test.ts` 另覆盖真实 SQLite FTS 查询、
版本 1 升级、trigram 不可用的模拟、能力恢复后的重建、候选/正文事务一致性、Unicode
结果等价、热缓存复用与搜索取消。Zotero 的连接包装器和大文库耗时仍需在宿主环境中验证。
