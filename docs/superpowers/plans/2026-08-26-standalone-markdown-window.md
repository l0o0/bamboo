# Standalone Markdown Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Bamboo Markdown attachments stable `zmd-` stored filenames and a single-instance standalone editor window accessible from the sidebar more menu.

**Architecture:** Generalize the existing tab session just enough to distinguish a Zotero tab host from a standalone chrome-window host while retaining one editor shell, save path, image pipeline, and focus-sync implementation. A focused `MarkdownWindowRegistry` owns one standalone window per attachment item; the sidebar delegates its two opening commands to the existing tab opener and the new window opener.

**Tech Stack:** TypeScript 6, Zotero 9/10 chrome/XHTML APIs, CodeMirror 6 iframe, Fluent localization, Node test runner via `tsx`, pnpm.

## Global Constraints

- The physical stored filename is exactly `zmd-{logical filename}.md`, with one `zmd-` prefix and one `.md` suffix.
- The Zotero attachment title, frontmatter title, H1, tab title, sidebar title, and window title do not expose the physical `zmd-` prefix.
- One attachment item ID can own at most one standalone window process-wide; repeated opens focus and refresh it.
- A sidebar, tab, and one standalone window may edit the same item concurrently through `DocumentSyncRegistry` focus refresh.
- The standalone window reuses the existing toolbar, outline, editor iframe, preview, status bar, saving, title sync, and image lifecycle.
- The sidebar more menu contains only “Open in Tab” and “Open in Standalone Window”; the old leading open-tab toolbar button is removed.
- Closing a standalone window saves with image cleanup before destroying the session; a failed save keeps the window open.
- Do not overwrite the pre-existing uncommitted document-info copyability changes in `src/modules/markdown/styles.ts` and `test/markdown-modal.test.ts`.

- [ ] **Step 3: Implement the pure naming helpers**

```ts
const STORED_PREFIX = "zmd-";

export function storedMarkdownFilename(logicalFilename: string): string {
  const logical = normalizeMarkdownFilename(logicalFilename).replace(
    /^zmd-/i,
    "",
  );
  return `${STORED_PREFIX}${logical}`;
}

export function logicalMarkdownFilename(storedFilename: string): string {
  return normalizeMarkdownFilename(storedFilename.replace(/^zmd-/i, ""));
}
```

`createMarkdownImportPaths()` places the timestamp/random uniqueness in a
`bamboo-{uniqueID}` directory and returns a file whose basename is generated by
`storedMarkdownFilename()`.

Remove `tmpDirectory`, not only the file, in `finally`. Keep `title: filename`
on `importFromFile()` so the item title remains logical.

- [ ] **Step 5: Preserve physical naming during explicit rename**

`storedMarkdownFilename(newLogicalName)` to `renameAttachmentFile()`, then set

- [ ] **Step 3: Implement the registry without Zotero globals**

Use one `Map<number, Entry>` where an entry owns `opening`, `window`, `session`,
and `closing`. Never retain document text. `open()` returns the existing opening
promise or focuses the live window before returning it.

- [ ] **Step 4: Add a script-free chrome XHTML host**

```xml
<?xml version="1.0"?>
<?xml-stylesheet href="chrome://global/skin/" type="text/css"?>
<window xmlns="http://www.mozilla.org/keymaster/gatekeeper/there.is.only.xul"
        xmlns:html="http://www.w3.org/1999/xhtml"
        id="bamboo-markdown-window"
        width="1024" height="760"
        minwidth="640" minheight="480">
  <html:div id="bamboo-markdown-window-root" />
</window>
```

No inline script or inline SVG is allowed. TypeScript attaches the load/focus/
close listeners to the returned window.

- [ ] **Step 5: Implement Zotero window creation and shared mounting**

Use the active/main Zotero window’s `openDialog()` with
`chrome://bamboo/content/markdownWindow.xhtml` and
`chrome,dialog=no,resizable,centerscreen`. On load, inject Markdown styles,
create a `surface: "window"` session, and mount the shared editor shell into
`#bamboo-markdown-window-root`.

- [ ] **Step 6: Implement focus and guarded close lifecycle**

On `focus`, call the session’s focus refresh. On the first native close event,
prevent closing, force-save with image cleanup, and check `save.lastError`.
Only call `window.close()` with `allowClose = true` after a successful save.
Always release listeners, registry entry, editor session, and DOM references.

- [ ] **Step 7: Wire shutdown cleanup and exports**

Export the opener from `src/modules/markdown/index.ts`, call
`closeAllMarkdownWindows()` before global toolkit teardown, and expose an API
method only if the existing public API surface has a matching open operation.
